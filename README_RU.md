# HOI4 AI Modding Skills

[简体中文](README.md) | [English](README_EN.md) | [日本語](README_JA.md) | Русский

Этот репозиторий содержит три навыка (Agent Skills) для поддержки, диагностики,
улучшения и создания модов Hearts of Iron IV с помощью Codex, ChatGPT, Cursor,
Claude Code и Gemini CLI.

Основное внимание уделяется работе с существующими модами: изучению незнакомой
кодовой базы, поиску ошибок между файлами, проверке производительности и
совместимости, а также подготовке конкретного плана исправления по данным о сбое.
При этом сохраняется полный путь от идеи, изложенной обычным языком, до игрового
контента на PDX — в том числе для пользователей, которые ещё не знают язык
сценариев HOI4.

Возможности, примеры запросов и рекомендации по постановке задачи описаны в
[руководстве пользователя на английском](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.en.md)
и [версии на упрощённом китайском](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.zh-CN.md).
Эти файлы предоставляются пользователю по запросу. Входные файлы навыков содержат
правило выдачи руководства; агенту предписано не загружать его полный текст по умолчанию.

В репозитории также есть необязательная интеграция **Codex Plugin**. Плагин
объединяет три навыка и локальный MCP-сервер с доступом только для чтения. Навыки
задают порядок разработки, ревью и проверки, а сервер помогает обнаружить
установку HOI4, проследить использование идентификаторов, проверить изменённые
через Git файлы, прочитать журналы и изучить метаданные медиафайлов. Все операции
MCP выполняются локально, не требуют облачной библиотеки файлов HOI4 или ключа
OpenAI API и не предоставляют возможностей запуска игры или изменения файлов
мода. Архитектура, интерфейсы инструментов и ограничения описаны в документе
[«Локальный плагин и помощник MCP»](docs/LOCAL_MCP_PLUGIN.md).

## Навыки в составе пакета

| Навык | Основное назначение |
| --- | --- |
| `hoi4-review-debug` | Улучшение существующих модов, межфайловый анализ Mod Doctor, журналы и сбои, производительность, совместимость, баланс, UX, проверка значков и ресурсов |
| `hoi4-pdx-modding` | PDX-скрипты, области действия (scopes), жизненный цикл, межфайловые контракты, локализация, миграция версий, техническая документация, комментарии и статическая проверка |
| `hoi4-content-builder` | Создание событий, решений, фокусов, персонажей, национальных духов (ideas), MIO, GUI, ИИ, OOB, карт, музыки, моделей и целых систем по описанию обычным языком |

**Рекомендуется устанавливать все три навыка вместе.** Они используют общие
правила проверки, рабочие процессы и ссылки на материалы друг друга.
`content-builder` превращает требования в готовый контент, `pdx-modding`
обеспечивает проверку языка и версии, а `review-debug` отвечает за сопровождение,
регрессионные проверки и данные о работе в игре. Отдельный навык может
загрузиться, но без соседних материалов не обеспечит полный рабочий процесс.

## Установка

### Рекомендуемый вариант для Codex: навыки и локальные инструменты

В Windows клонируйте или распакуйте репозиторий и выполните из его корня:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-codex-plugin.ps1
```

Скрипт устанавливает полный плагин в каталог локальных данных приложений текущего
пользователя и регистрирует его через Codex CLI. Он не изменяет HOI4, не запускает
игру и не загружает локальные файлы в сеть. После установки создайте новую задачу
Codex: в ней будут доступны три навыка и пять локальных инструментов только для
чтения. После обновления репозитория повторите ту же команду, чтобы обновить плагин.

Требования: Windows, Python 3 и Codex CLI. `ffprobe` необязателен: он лишь добавляет
сведения об аудио- и видеопотоках. Описание инструментов, ограничений и устранения
неполадок — в документе [«Локальный плагин и помощник MCP»](docs/LOCAL_MCP_PLUGIN.md).

### Только навыки

Скачайте полный пакет из раздела
[Releases](https://github.com/Fostanico/hoi4-ai-modding-skills/releases) или
клонируйте репозиторий. Скопируйте три каталога из `skills/` в одно из мест:

- `<MOD_ROOT>/.agents/skills/` — для конкретного репозитория мода;
- `$HOME/.agents/skills/` — для текущего пользователя и нескольких модов.

Сохраняйте взаимное расположение `SKILL.md`, `references/`, `workflows/`, `assets/`,
`scripts/` и `agents/` внутри каждого навыка. Установка в проект удобна для
совместного сопровождения с модом, а установка для пользователя — для повторного
использования в разных проектах.

Этот способ подходит и для клиентов без поддержки плагинов. Локальные
инструменты MCP при этом не устанавливаются.

Обычно Codex обнаруживает изменения автоматически. Если навык не появился,
перезапустите клиент. В Codex CLI или расширении для IDE используйте `/skills`
для просмотра списка и имя вроде `$hoi4-review-debug` для явного вызова.
В настольном приложении ChatGPT навыки доступны на странице Skills в боковой
панели. Расположение и способы вызова также описаны в
[документации OpenAI по Skills](https://learn.chatgpt.com/docs/build-skills).

Дополнительные сведения о платформах и пакетах — в
[руководстве по установке и распространению](docs/INSTALLATION.md).

### Cursor Agent

Cursor обнаруживает навыки проекта в `.agents/skills/` или `.cursor/skills/`,
а пользовательские — в `~/.agents/skills/` или `~/.cursor/skills/`. Скопируйте
все три каталога из `skills/` в одно из этих мест, затем заново откройте или
обновите Agent. Для явного вызова введите `/` в чате Agent и найдите навык по имени.

Cursor Agent передаёт навыки выбранной модели: пакет не привязан к одной модели.
Навыки проекта можно хранить в системе контроля версий вместе с модом. Чтобы
использовать личные `~/.cursor/skills/` в Cloud Agents, включите синхронизацию
Skills в настройках Cursor. Копирование навыков не устанавливает локальный
помощник MCP для Codex. Пути, способы вызова и ограничения удалённых агентов
описаны в [официальной документации Cursor Agent Skills](https://cursor.com/docs/skills).

## Примеры использования

Сопровождение существующего мода можно начать с ревью без изменения файлов:

> `$hoi4-review-debug` Проверь этот мод. Сначала прочитай техническую документацию
> проекта и связанные тексты для игрока, затем проверь межфайловые ссылки,
> жизненный цикл переменных, производительность периодических обработчиков,
> значки, локализацию и совместимость зависимостей. Сначала представь
> подтверждённые выводы и план исправления, не изменяя файлы.

При анализе журналов по возможности укажите путь к моду, версию игры,
включённые зависимости и приложите актуальный `error.log`:

> Проанализируй этот `error.log`. Раздели проблемы этого мода, зависимостей,
> базовой игры и необязательных медиафайлов. Сгруппируй повторяющиеся сообщения
> по первопричине и предложи минимальное исправление для каждой группы.

Для нового контента достаточно описать желаемую механику и ограничения:

> `$hoi4-content-builder` Создай набор повторяемых решений для HOI4 1.19 с весами
> выбора для ИИ и локализацией на английском, упрощённом китайском, русском и
> японском. До реализации проверь актуальный синтаксис базовой игры, а после
> завершения выполни статическую проверку.

Явный вызов необязателен. Совместимый агент может выбрать навык автоматически,
если запрос соответствует описанию в `SKILL.md`. Указывать имя удобно, когда
нужен конкретный порядок ревью или диагностики.

## Основные рабочие процессы

Все три навыка следуют [общим правилам работы](skills/hoi4-pdx-modding/references/workflow-boundaries.md):
повторно используют актуальные доказательства, после локальной правки проверяют
только затронутые части и обновляют документацию при изменении описанного контракта.
Бюджет короткого теста включает подготовку и восстановление настроек; начальное
состояние выбирается по задаче — текущая сессия, тестовое сохранение или новая игра.
По команде пользователя работа прекращается с краткой передачей текущего состояния.

### Улучшение существующего мода

1. Прочитать техническое руководство проекта, записи передачи работы и связанные тексты для игрока, чтобы понять исходный замысел.
2. Построить связи между событиями, решениями, effects, triggers, переменными, flags, локализацией, GUI и GFX.
3. Отделить подтверждённые дефекты, риски совместимости и проблемы производительности от игровых решений, требующих выбора автора.
4. Если требуется согласование, представить доказательства и поэтапный план до редактирования.
5. Вносить изменения только в согласованных пределах. Для маленькой правки достаточно просмотра diff, для обычной — проверки изменённых файлов, для крупной — подходящих расширенных проверок. Избегать лишних запусков и отмечать, где ещё нужны данные из игры.

### Диагностика журналов и сбоев

1. Группировать сообщения `error.log` по первопричинам, отдавая приоритет ошибкам разбора, областей действия, оборудования, идеологий и локализации.
2. Сопоставлять время журнала, активный плейсет и последние действия игрока с реальными путями выполнения кода. Последняя строка журнала сама по себе не доказывает причину сбоя.
3. При необходимости анализировать минидамп Windows, указывая степень уверенности и недостающие данные.
4. Получать поэтапное согласие пользователя перед использованием WinDbg, Ghidra, полных дампов пользовательского процесса, подключением к процессу или аппаратными точками останова по данным.

### Разработка нового контента

1. Преобразовать описание задачи в границы реализации, состояния, ресурсы, поведение ИИ, правила совместимости и критерии приёмки.
2. Проверить синтаксис и токены по документации установленной версии, действующим примерам базовой игры и точным версиям включённых зависимостей.
3. Создать связанные скрипты, GFX, ресурсы и локализацию на основе проверенных шаблонов и комплектов, не оставляя изолированных определений.
4. Соразмерно изменениям проверить кодировку, межфайловые ссылки, затронутые комментарии и документацию. Если нужны данные из игры, соблюдать разрешённый объём и бюджет тестирования.

## Что можно проверить

- Синтаксис PDX, цепочки областей действия, цели событий, жизненный цикл переменных и флагов
- События, решения, фокусы, национальные духи, персонажей, MIO, оборудование, технологии, ИИ и состав войск (OOB)
- Часто выполняемые пути `on_actions`, глобальные обходы, периодичность и переход к обработке по событиям
- Кодировку локализации, дубли ключей, цвета, значки, форматирование переменных, scope functions и многоязычные шаблоны
- Регистрацию GUI/GFX, значки духов, решений и черт, пути текстур, аудио и ресурсы зависимостей
- Требования к DDS загрузочных экранов, именованных лётчиков-асов, особые черты, значки и фиксированные портреты оперативников
- Ветви совместимости с базовой игрой и крупными модами, миграцию версий и риски жизненного цикла сохранений
- Игровые циклы, числовой баланс, доступность механик для ИИ, обратную связь, способы противодействия и удобство игрока
- Технические руководства, записи передачи работы, понятные комментарии, результаты проверок и подготовку к выпуску
- `error.log`, дампы сбоев, WinDbg и углублённую нативную диагностику с согласия пользователя

## Инженерные возможности

- Набор регрессионных сценариев по реальным диалогам:
  `evals/real-dialogue-regression.json`. Запросы анонимизированы, а исходные
  формулировки представлены отпечатками SHA-256. Закрытые диалоги и идентификаторы
  частных проектов не публикуются.
- Mod Doctor 2 умеет определять активный плейсет, ограничивать анализ изменениями
  Git, сравнивать результаты с прошлой базовой проверкой и применять временные
  исключения. Подтверждённые проблемы отделяются от эвристических предположений;
  доступны форматы Text, JSON, Markdown и SARIF.
- Многофайловые комплекты охватывают цепочки игрового контента, включая разблокировку
  оборудования технологиями и начальную инициализацию по игровым правилам.
- `assets/template-manifest.json` хранит целевую сборку, исходные примеры использования,
  даты проверки и обязательные проверки. Валидатор следит, чтобы каждый файл
  шаблона или комплекта был зарегистрирован ровно один раз.
- Работа с медиа учитывает метаданные DDS, явные ссылки и обоснованные варианты
  преобразования. Хеширование включается только для конкретного поиска дубликатов
  или сравнения содержимого. Загрузочные изображения, mipmap, cubemap и материалы
  моделей обрабатываются с учётом требований их потребителей.

## Ограничения и границы действий

Навыки предписывают агенту сверять выводы с файлами целевой версии игры,
установленной документацией, реально включёнными зависимостями и текстами для
игрока. Вики и руководства сообщества помогают найти направление поиска,
но не заменяют проверку актуальной версии.

Статическая проверка не доказывает, что GUI, MIO, области действия событий или
ветви совместимости работают в игре. Запуск Steam, управление игрой, установка
диагностических инструментов, обратная разработка, подключение к процессу и сбор
полной памяти требуют объяснения цели и границ действий, а также согласия пользователя.

  `.agents/skills/` в проекте; введите `/` для поиска и вызова навыка.
- Claude Code: `~/.claude/skills/` или `.claude/skills/` в проекте.
- Gemini CLI: `~/.gemini/skills/`, `~/.agents/skills/` или поддерживаемый каталог рабочей области.
- Клиенты с загрузкой пользовательских навыков: установите все три ZIP-файла
  навыков из одного релиза. Установка отдельного навыка рассчитана на опытных
  пользователей, которые осознанно принимают отсутствие соседних рабочих процессов.

Пути обнаружения могут меняться. Перед установкой сверяйтесь с актуальной
документацией используемого клиента.
