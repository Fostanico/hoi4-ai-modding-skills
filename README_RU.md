# HOI4 AI Modding Skills

[简体中文](README.md) | [English](README_EN.md) | [日本語](README_JA.md) | Русский | [한국어](README_KO.md)

Набор из трёх модульных Agent Skills для работы с модами *Hearts of Iron IV* в **Codex, Google Antigravity, Cursor, Claude Code, Gemini CLI и ChatGPT**.

Главный фокус пакета — **сопровождение, аудит и развитие существующих модов**: разбор сложной кодовой базы, поиск межфайловых ошибок, оптимизация производительности, проверка совместимости и расследование вылетов. При этом набор полностью сохраняет возможность **создавать новый контент и целые моды с нуля по описанию на обычном языке**, не вникая заранее в тонкости PDX-скрипта.

Полное руководство по совместной работе с ИИ — от постановки задачи, скриптов и сохранений до GUI, шейдеров, ресурсов, локализации, диагностики и публикации — доступно на пяти языках:
[Русский](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ru.md) |
[简体中文](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.zh-CN.md) |
[English](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.en.md) |
[日本語](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ja.md) |
[한국어](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ko.md).
Руководство адресовано читателю и выдаётся по запросу: в точках входа навыков хранится только правило выдачи, чтобы не расходовать контекст в обычной работе.

В репозиторий также входят два **физически разделённых** локальных MCP-сервера без сторонних зависимостей:
- **Помощник только для чтения `hoi4_local`** (в составе Codex Plugin): находит установку HOI4, отслеживает идентификаторы по файлам, проверяет изменения Git, читает журналы и анализирует метаданные медиафайлов — полностью локально, без ключей API и без права записи. Подробности: [«Локальный плагин и помощник MCP»](docs/LOCAL_MCP_PLUGIN_RU.md).
- **Опциональный сервер для тестирования в игре `hoi4_desktop`** (отключён по умолчанию): даёт клиентам без встроенного управления рабочим столом (Google Antigravity, Cursor, Claude Code, Gemini CLI) безопасные скриншоты и ввод в Windows со строгим белым списком процессов (`hoi4.exe`, Paradox Launcher, Steam). Подробности: [«Настройка локального desktop MCP»](docs/DESKTOP_MCP_SETUP_RU.md).

## Как распределены три навыка

| Навык | Специализация |
| --- | --- |
| `hoi4-review-debug` | Аудит существующих модов, межфайловый Mod Doctor, анализ журналов и вылетов, производительность, совместимость, баланс, UX и проверка ресурсов |
| `hoi4-pdx-modding` | Синтаксис PDX и области действия (scopes), жизненный цикл переменных и сохранений, межфайловые контракты, локализация, миграция версий, документация и статическая проверка |
| `hoi4-content-builder` | Создание с нуля событий, решений, фокусов, персонажей, национальных духов, MIO, GUI, ИИ, OOB, карт, музыки, моделей и целых систем по описанию на обычном языке |

**Устанавливайте все три навыка вместе.** Они работают как единая мастерская: `content-builder` превращает замысел в связанный игровой контент, `pdx-modding` следит за актуальным синтаксисом и контрактами, а `review-debug` берёт на себя аудит, регрессии и проверку в игре. Вместе они сохраняют все перекрёстные ссылки и полный рабочий цикл.

## Установка

### Codex: навыки + локальный MCP только для чтения (рекомендуется)

В Windows клонируйте или распакуйте репозиторий и выполните из корня:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-codex-plugin.ps1
```

Скрипт установит плагин в локальный каталог данных пользователя и зарегистрирует его через Codex CLI, не затрагивая файлы игры, не запуская Steam и ничего не отправляя в сеть. После установки **откройте новую задачу Codex** — три навыка и пять инструментов только для чтения сразу станут доступны. После обновления репозитория просто повторите команду.

Требования: Windows, Python 3 и Codex CLI (`ffprobe` опционален для подробных сведений об аудио- и видеопотоках). Подробности — в [«Локальный плагин и помощник MCP»](docs/LOCAL_MCP_PLUGIN_RU.md).

### Только навыки (для любых клиентов)

Скачайте пакет из [Releases](https://github.com/Fostanico/hoi4-ai-modding-skills/releases) или клонируйте репозиторий, затем скопируйте три каталога из `skills/` в нужное место:

- **На уровне проекта** (хранится вместе с модом): `<MOD_ROOT>/.agents/skills/`
- **На уровне пользователя** (общий для всех модов): `$HOME/.agents/skills/`

Сохраняйте структуру `SKILL.md`, `references/`, `workflows/`, `assets/`, `scripts/` и `agents/` внутри каждого каталога.

- **Codex и ChatGPT**: Codex обычно подхватывает обновления сам (при необходимости перезапустите клиент). Список доступен по `/skills`, а явный вызов — через `$hoi4-review-debug`; в настольном ChatGPT навыки отображаются на странице Skills. См. [документацию OpenAI по Skills](https://learn.chatgpt.com/docs/build-skills).
- **Cursor**: автоматически находит `.agents/skills/` и `.cursor/skills/` в проекте и в домашнем каталоге `~/`. Переоткройте или обновите Agent; в чате навык можно вызвать явно через `/`. Навыки работают с любой выбранной моделью; для Cloud Agents включите синхронизацию `~/.cursor/skills/` в настройках Cursor. См. [документацию Cursor Agent Skills](https://cursor.com/docs/skills).
- **Google Antigravity, Claude Code и Gemini CLI**: разместите три навыка в каталоге вашего клиента и при желании подключите локальные MCP-серверы `hoi4_local` и `hoi4_desktop`.

Полный справочник по платформам и правилам распространения: [«Установка и распространение»](docs/INSTALLATION_RU.md).

## Примеры запросов

**Провести аудит существующего мода до первых правок:**

> `$hoi4-review-debug` Проведи аудит этого мода. Сначала прочитай техническое руководство проекта и связанные тексты для игрока, затем проверь межфайловые ссылки, жизненный цикл переменных, нагрузку периодических обработчиков, значки, локализацию и совместимость с зависимостями. Сначала покажи отчёт с доказательствами и поэтапный план правок, ничего не меняя.

**Разобрать `error.log` по первопричинам:**

> Проанализируй этот `error.log`. Раздели ошибки этого мода, зависимостей, базовой игры и необязательных медиафайлов. Объедини повторы по первопричинам и предложи минимальное чистое исправление для каждой группы.

**Создать новый контент обычным языком:**

> `$hoi4-content-builder` Сделай набор повторяемых решений для HOI4 1.20 с весами для ИИ и локализацией на русском, английском, упрощённом китайском, японском и корейском. Сначала проверь синтаксис по актуальной базовой игре, затем запусти статическую проверку изменённых файлов.

Указывать имя навыка каждый раз необязательно: совместимый агент сам выберет подходящий по описанию в `SKILL.md`. Явный вызов удобен, когда нужен строгий сценарий аудита или расследования сбоя.

## Основные рабочие процессы

Все три навыка соблюдают [общие границы работы](skills/hoi4-pdx-modding/references/workflow-boundaries.md): переиспользуют актуальные доказательства, после локальной правки перепроверяют только затронутое, обновляют документацию при изменении реальных контрактов, включают подготовку и восстановление в бюджет короткого игрового теста и немедленно останавливаются по вашей команде с лаконичным отчётом.

### 1. Развитие и рефакторинг существующего мода

1. Прочитать техническую документацию, заметки передачи и тексты для игрока, чтобы точно понять замысел.
2. Проследить реальные связи между событиями, решениями, effects, triggers, переменными, флагами, локализацией и GUI/GFX.
3. Развести подтверждённые дефекты, риски совместимости, узкие места производительности и дизайнерские вопросы, требующие решения автора.
4. Когда нужно согласование, представить доказательства и поэтапный план до редактирования.
5. Вносить правки строго в согласованных границах, подбирать глубину проверки под размер diff (просмотр diff для мелочей, проверка изменённых файлов для обычных правок, расширенный аудит для крупных рефакторингов) и честно отмечать, что стоит увидеть в игре.

### 2. Диагностика журналов и вылетов

1. Сгруппировать `error.log` по первопричинам, начиная с ошибок парсера, областей действия, оборудования, идеологий и конфликтов локализации.
2. Сопоставить метки времени, активный плейсет и последние действия игрока с реальным кодом, не принимая последнюю строку журнала за приговор.
3. При необходимости разобрать Windows minidump с указанием уровня уверенности и недостающих данных.
4. Переходить к WinDbg, Ghidra, полным дампам памяти, подключению к процессу и аппаратным точкам останова только с поэтапного согласия пользователя.

### 3. Создание нового контента

1. Перевести описание на обычном языке в границы, владение состоянием, ресурсы, логику ИИ, требования совместимости и критерии приёмки.
2. Сверить синтаксис и токены с установленной версией игры, поставляемой документацией и включёнными зависимостями.
3. Собрать скрипты, GFX, ресурсы и локализацию из проверенных шаблонов и комплектов со всеми связанными точками входа.
4. Проверить кодировку, ссылки и затронутые документы соразмерно задаче, а при запуске игры соблюдать согласованный объём и бюджет времени.

## Охват

- **Скрипты и состояние**: синтаксис PDX, цепочки scope, цели событий, жизненный цикл переменных и флагов
- **Игровые системы**: события, решения, фокусы, национальные духи, персонажи, MIO, оборудование, технологии, ИИ и OOB
- **Производительность**: горячие пути `on_actions`, глобальные обходы, переход к событиям и порционной обработке
- **Локализация**: UTF-8 с BOM, дубли ключей, цвета и значки, форматирование переменных, scope functions, многоязычные шаблоны
- **Интерфейс и медиа**: регистрация GUI/GFX, значки, пути текстур, аудио, требования к DDS экранов загрузки, именованные асы, черты и портреты оперативников
- **Совместимость и миграция**: ветви под базовую игру и глобальные моды, переход на новые версии, сохранность старых сохранений
- **Опыт игрока и документация**: игровые циклы, баланс, доступность для ИИ, обратная связь и контрмеры, технические руководства, понятные комментарии и предрелизная проверка
- **Глубокая диагностика**: разбор `error.log`, дампы сбоев, WinDbg и расширенный нативный анализ с согласия пользователя

## Инженерная база

- **Регрессия на реальных диалогах**: `evals/real-dialogue-regression.json` хранит обезличенные практические задачи с отпечатками SHA-256 без публикации закрытых переписок и частных проектов.
- **Mod Doctor 2**: определяет активный плейсет, умеет проверять только изменения Git, сравнивать с прошлым срезом и применять временные исключения; разделяет подтверждённые ошибки и эвристические сигналы, выгружая отчёт в Text, JSON, Markdown или SARIF.
- **Многофайловые комплекты**: охватывают типовые цепочки контента, а также связки «технология → оборудование» и стартовую инициализацию по игровым правилам.
- **Манифест шаблонов**: `assets/template-manifest.json` фиксирует целевую сборку, эталонные примеры из базовой игры, даты проверки и обязательные тесты, а валидатор контролирует полноту регистрации.
- **Аудит медиа по месту применения**: анализирует метаданные DDS, явные ссылки и кандидатов на оптимизацию; хеширование включается по запросу для поиска дублей, а экраны загрузки, mipmap, cubemap и материалы моделей сохраняют свои технические требования.

## Принципы доказательности и безопасности

- **Опора на живую сборку**: агент сверяет решения с файлами целевой установки, её документацией, реально включёнными зависимостями и текстами для игрока. Вики и статьи сообщества служат ориентиром, а последнее слово остаётся за вашей версией игры.
- **Разделение ролей проверок**: статика отлавливает синтаксис, ссылки, кодировку и связку файлов; отображение GUI, работу MIO, сложные scope и совместимость модов подтверждает запуск в игре.
- **Явное согласие на повышенные действия**: запуск Steam, управление окнами игры, установка отладчиков, реверс-инжиниринг, подключение к процессу и сбор полной памяти всегда начинаются с объяснения цели, границ и рисков — и выполняются только после вашего одобрения.
