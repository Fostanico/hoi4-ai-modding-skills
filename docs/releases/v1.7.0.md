# HOI4 AI Modding Skills v1.7.0

## 中文

本次发布汇总 **v1.6.0 之后的全部提交**，包括此前已推送的测试流程、将领技能和球形
地图研究，以及本次新增的 GUI 着色器、用户指南和发布整理。

### GUI 着色器：从技术研究到可复用接入规则

- 新增 `gui-shader-effects.md` 接入契约和 `gui-shader-recipes.md` 算法配方，
  并接入开发、内容制作和审查三套技能的按需路由。
- 从测试工程及 Claude 编写的实现中归纳动态超事件、透视全息卡片、启动界面、
  选项文字悬停染色、暖光、扫描和装饰地球的实现方式。具体覆盖 RGB 控制图集、
  像素中心采样、预烘焙模糊、图像空间光束、程序化花瓣、射线与平面求交、按钮
  状态入口、时间戳终态回退、透明混合和生成器维护。
- 明确渲染与交互的接口：视觉透视或动画不会自动移动原生 GUI 点击区域，也不能
  假设着色器能读取鼠标坐标。区分 DX9、DX11、GLSL 及不同采样器、图集的要求。
- 提供独立编写、不含项目美术的 `gui-shader-example` 最小渲染组件和编译记录。
  它需要用户补充纹理与 GUI 挂载，不是可直接启用的完整 MOD。静态扫描新增
  `.shader` / `.fxh` 文件覆盖，并补充研究来源与署名。

### 用户指南与 AI 技术资料分开维护

- 内置中文用户指南，介绍这套技能能做什么、常见效果、适用边界，以及如何用
  自然语言描述需求；中英文 README 均提供入口。
- 用户指南位于 `assets/user-guides/`。技能入口只保留按需交付规则，默认不读取
  正文；用户询问能力或使用方式时提供文件。用户明确要求讨论、修改或翻译该
  指南时，才读取所需部分。
- AI 技术资料以接入契约、输入输出、步骤、验证与失效条件组织，按任务加载，
  不重复装入面向用户的说明。

### 球形地图研究与真实交互边界

- 吸收 Globe Mod 0.2.0 的通用思路：逻辑坐标与显示坐标分离、焦点保持、连续
  曲率过渡、跨渲染层一致投影、背面裁剪、天空补球及同路径完整文件覆盖兼容。
- 记录用户最新实测：在其测试组合中兼容性良好，但鼠标拾取误差随相机高度及
  离屏幕中心的距离增加。把中心、边缘和不同缩放高度纳入验证。
- 区分源码观察、数值检查、用户实测，以及对引擎拾取原因的推断；不把 GPU
  显示变化等同于引擎逻辑或拾取更新。仅吸收独立改写的方法，不分发原 MOD
  的着色器或美术素材。

### 将领技能解析与回归防护

- 新增 `leader-abilities.md`，记录错误定义导致同文件后续技能未加载的解析
  级联。新增技能优先追加在既有 `ability` 根块末尾、闭合括号之前，保留原 ID
  和顺序；追加位置不代替正确性验证。
- 补充 `one_time_effect` 层级、消费者实际支持的 modifier、trait 解锁链、图标
  和延时恢复事件检查，并同步模板、审查清单和三套技能入口。
- 新增匿名真实对话回归案例，强化通用经验脱敏、适度验证和验证后的 Git 交付。

### 更尊重用户偏好与资源预算的实机测试

- 合并此前五次流程提交：先确认当前工具能否操作原生 Steam、启动器和 HOI4，
  再判断用户授权与实际额度/费用；不按客户端品牌推断桌面控制能力。
- 可用时读取可信套餐、额度和计费元数据，缺少元数据不等于 API 计费。结合
  实际操作范围，将测试分为轻微、有限和高成本，遵守既有预算和停止条件。
- 采用用户最新选择及仍适用的授权，每项任务最多询问一次；不重复催问，不把
  沉默当作新授权。用户拒绝测试或缺少原生控制能力时完成静态工作，按需交付
  简短人工测试路径。
- 同步内容制作、媒体优化、既有 MOD 改进与回归工作流，避免入口规则互相矛盾。

### 版本、验证与安装

- 本次技术资料延续已核验的 **HOI4 Operation Postern 1.19.3.0 (5632)** 基线。
  这不是对所有游戏版本或渲染后端的运行时兼容保证。
- 发布检查覆盖技能目录及链接、模板清单、匿名对话回归、PowerShell 解析、
  Mod Doctor fixtures、多文件套件和本地只读 MCP 协议烟雾测试。
- 新最小组件的 10 个 DX9/DX11 HLSL 程序均独立编译通过；这不证明游戏中的
  资源绑定、Clausewitz 包装器或 GLSL 后端。当前测试工程的启动 UI 已获用户
  实机验收确认，此结论保留为用户报告，不外推到全部示例或后端。
- 插件版本更新至 **1.7.0**。继续提供完整包、三个独立 Skill ZIP 与
  `SHA256SUMS-1.7.0.txt`；安装时使用同一版本的三套技能。发布包从提交中的
  文件构建，排除本机缓存和临时输出，保留许可证及署名。固定 `.shader` /
  `.fxh` 的 LF 换行，使 Windows 签出及发布包与编译记录的源码哈希一致。

## English

This release covers **every commit after v1.6.0**, including the previously
pushed testing workflow, leader-ability safeguards, and globe-map research,
alongside the new GUI shader resources, user guide, and release preparation.

### GUI shaders: reusable integration rules from working studies

- Added `gui-shader-effects.md` integration contracts and
  `gui-shader-recipes.md` algorithms, with on-demand routing from all three
  development, content-building, and review skills.
- Extracted reusable techniques from the test project and Claude-authored
  implementations: animated super-events, perspective holographic cards,
  startup UI, hover text tinting, warm lighting, scans, and decorative globes.
  Topics include RGB control atlases, texel-centre sampling, baked blur,
  image-space light shafts, procedural petals, ray-plane intersections,
  button-state entrypoints, terminal-state clock fallbacks, alpha blending,
  and generator maintenance.
- Defined the rendering/input boundary: visual perspective and animation do
  not automatically move native GUI hit areas, and mouse coordinates cannot
  be assumed available to a shader. Documented backend, sampler, and atlas
  differences across DX9, DX11, and GLSL.
- Added an independently written `gui-shader-example` rendering component
  without project artwork, plus its compile record. It requires a supplied
  texture and owning GUI; it is not a complete installable mod. Static scans
  now cover `.shader` / `.fxh`, with updated provenance and attribution.

### Separate user guidance from AI technical context

- Bundled a Simplified Chinese user guide covering capabilities, common
  effects, limits, and example plain-language requests. Both READMEs link to it.
- The guide lives under `assets/user-guides/`. Skill entrypoints retain only
  the on-demand delivery rule and instruct agents not to read its body by
  default. Agents provide the file when users ask about capabilities or usage,
  and read relevant portions only when explicitly asked to discuss, edit, or
  translate it.
- AI references use integration contracts, inputs/outputs, procedures,
  validation, and failure conditions, loaded as needed without duplicating
  the user-facing explanation.

### Globe-map research and real input limits

- Captured general techniques from Globe Mod 0.2.0: separating logical and
  display coordinates, keeping the focal point stable, continuous curvature,
  consistent projection across rendering layers, backface clipping, sky-based
  globe completion, and compatibility of full-file path overrides.
- Recorded the user's corrected runtime findings: compatibility was good in
  the tested setup, while picking error grew with camera height and distance
  from the screen centre. Verification now covers central/edge picking at
  different zoom heights.
- Distinguished source observations, numerical checks, user runtime reports,
  and inferred engine causes. GPU presentation changes do not establish
  updated engine logic or picking. Only independently rewritten methods are
  included; the original mod's shaders and artwork are not redistributed.

### Leader-ability parsing and regression safeguards

- Added `leader-abilities.md` for parser cascades in which a malformed
  definition prevents later abilities in the same file from loading. New
  abilities should normally be appended inside the existing `ability` root
  block, before its closing brace, preserving established IDs and ordering.
  Append position does not replace validation.
- Added checks for `one_time_effect` nesting, modifiers supported by the
  actual consumer, trait unlock chains, icons, and delayed restoration events;
  updated the template, review checklist, and all three skill entrypoints.
- Added an anonymized real-dialogue regression case covering portable
  learning, proportionate validation, and Git delivery after verification.

### Runtime testing that respects user preferences and resource budgets

- Consolidated five earlier workflow commits. Check native Steam, launcher,
  and HOI4 control capability before user authorization and quota/cost impact;
  do not infer desktop-control capability from the client brand.
- Use trusted plan, quota, and billing metadata when available; missing
  metadata does not establish API billing. Classify tests as negligible,
  bounded, or expensive based on actual scope, honoring existing budgets and
  stopping conditions.
- Follow the user's latest choice and still-applicable authorization. Ask at
  most once per task, avoid repeated reminders, and never treat silence as new
  authorization. When the user declines or native control is unavailable,
  finish static work and provide a concise manual path only when useful.
- Updated content-building, media-optimization, existing-mod improvement,
  and regression workflows to keep their entry rules consistent.

### Version, validation, and installation

- The technical baseline remains the previously verified **HOI4 Operation
  Postern 1.19.3.0 (5632)**. This is not a runtime compatibility guarantee for
  every game version or rendering backend.
- Release checks cover skill trees and links, the template manifest,
  anonymized dialogue cases, PowerShell parsing, Mod Doctor fixtures,
  multi-file kits, and the local read-only MCP protocol smoke test.
- All 10 DX9/DX11 HLSL programs in the new minimal component passed independent
  compilation. This does not establish in-game resource binding, Clausewitz
  wrapper behavior, or GLSL compatibility. The user confirmed acceptance of
  the current test project's startup UI; that remains a user-reported result
  limited to that implementation and tested setup.
- Updated the plugin to **1.7.0**. Downloads include the full bundle, three
  individual Skill ZIPs, and `SHA256SUMS-1.7.0.txt`. Install all three skills
  from the same release. Archives are built from committed files, excluding
  local caches and temporary outputs while retaining licensing and attribution.
  `.shader` / `.fxh` use LF endings so Windows checkouts and release archives
  retain the source hashes recorded by the compiler check.
