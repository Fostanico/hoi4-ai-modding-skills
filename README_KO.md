# HOI4 AI 모딩 스킬

[简体中文](README.md) | [English](README_EN.md) | [日本語](README_JA.md) | [Русский](README_RU.md) | 한국어

이 저장소는 Codex, ChatGPT, Cursor, Claude Code, Gemini CLI로 Hearts of Iron IV 모드를
개발하고 유지·보수할 때 쓰는 에이전트 스킬 세 가지를 제공합니다.

기존 모드의 구조를 파악하고, 여러 파일에 걸친 오류를 추적하고, 성능과 호환성을 검토하는 데
중점을 둡니다. 충돌 로그를 바탕으로 수정 계획을 세우거나, PDX 스크립트를 모르는 상태에서
만들고 싶은 기능을 일상적인 말로 설명해 게임에서 쓸 수 있는 콘텐츠로 구현할 수도 있습니다.

요청 작성, 스크립트, 세이브, GUI, 미디어, 현지화, 오류 진단, 배포까지 다루는
HOI4 모드 개발 가이드를 참고하세요.

[简体中文](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.zh-CN.md) |
[English](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.en.md) |
[日本語](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ja.md) |
[Русский](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ru.md)

가이드는 사용자가 요청할 때 제공하는 문서입니다. 각 스킬의 `SKILL.md`에는 해당 언어의
파일을 찾는 방법이 적혀 있습니다. 일반 작업에서는 에이전트가 가이드 본문을 미리 읽지 않습니다.

선택 사항인 **Codex 플러그인**은 스킬 세 가지와 읽기 전용 로컬 MCP 서버를 함께 설치합니다.
스킬은 개발·검토·검증 절차를 제공하고, MCP 도구는 게임 설치 위치 찾기, 식별자 추적,
Git 변경 파일 검증, 로그 읽기, 미디어 메타데이터 확인을 지원합니다. MCP 작업은 로컬에서
실행되며 클라우드의 HOI4 자료나 OpenAI API 키가 필요하지 않습니다. 도구가 지원하는 작업과
권한 범위는 [로컬 플러그인 및 MCP 도구 안내](docs/LOCAL_MCP_PLUGIN.md)에 정리되어 있습니다.

## 포함된 스킬

| 스킬 | 주요 용도 |
| --- | --- |
| `hoi4-review-debug` | 기존 모드 개선, Mod Doctor로 여러 파일 검사, 로그와 충돌 진단, 성능·호환성·밸런스·사용성 검토, 아이콘과 에셋 점검 |
| `hoi4-pdx-modding` | PDX 스크립트, 스코프와 상태의 수명, 파일 간 연결 규칙, 현지화, 버전 이행, 기술 문서, 주석, 정적 검증 |
| `hoi4-content-builder` | 자연어로 요청한 이벤트, 결정, 국가중점, 인물, 국민정신, 군수 산업체(MIO), GUI, AI, 전투서열(OOB), 지도, 음악, 모델 등의 기능과 시스템 구현 |

**세 스킬을 함께 설치하세요.** 콘텐츠 빌더는 요구 사항을 완성된 기능으로 만들고, PDX 모딩
스킬은 대상 버전의 문법과 구현을 검증하며, 검토·디버그 스킬은 유지·보수와 회귀 점검,
실제 게임에서 얻은 증거를 다룹니다. 세 스킬은 검증 규칙과 작업 절차를 공유하고 서로의
자료를 참조합니다.

## 설치

### Codex에서 스킬과 로컬 도구 설치

Windows에서 이 저장소를 복제하거나 압축을 푼 뒤, 저장소 루트에서 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-codex-plugin.ps1
```

설치 스크립트는 현재 사용자의 로컬 앱 데이터 폴더에 플러그인을 복사하고 Codex CLI로
등록합니다. HOI4 파일 수정, 게임 실행, 로컬 파일 업로드는 수행하지 않습니다. 설치가 끝나면
Codex에서 새 작업을 시작하세요. 저장소를 업데이트한 뒤 같은 명령으로 플러그인을 갱신할 수
있습니다.

Windows, Python 3, Codex CLI가 필요합니다. `ffprobe`를 추가로 설치하면 오디오와 동영상
스트림의 메타데이터를 확인할 수 있습니다. 도구 목록과 문제 해결 방법은
[로컬 플러그인 및 MCP 도구 안내](docs/LOCAL_MCP_PLUGIN.md)를 참고하세요.

### 스킬만 설치

[Releases](https://github.com/Fostanico/hoi4-ai-modding-skills/releases)에서 전체 패키지를
내려받거나 저장소를 복제합니다. `skills/` 아래의 세 폴더를 설치 범위에 따라 복사합니다.

- 현재 모드에서만 사용하려면 `<MOD_ROOT>/.agents/skills/`
- 여러 모드에서 공통으로 사용하려면 `$HOME/.agents/skills/`

각 스킬의 `SKILL.md`와 `references/`, `workflows/`, `assets/`, `scripts/`,
`agents/`는 같은 폴더에 둡니다. 설치한 스킬이 보이지 않으면 클라이언트를 다시 열어 보세요.
플러그인을 지원하지 않는 클라이언트에서도 이 방식으로 스킬을 쓸 수 있습니다. 로컬 MCP
도구가 필요하면 위의 Codex 플러그인 설치 절차를 따르세요.

Codex CLI나 IDE 확장에서는 `/skills`로 설치된 스킬을 확인하고, 프롬프트에
`$hoi4-review-debug`처럼 이름을 넣어 명시적으로 호출할 수 있습니다. ChatGPT에서 스킬을
지원하는 계정은 Skills 화면에서 설치 상태를 확인할 수 있습니다. 설치 경로와 호출 방식은
[OpenAI 스킬 문서](https://learn.chatgpt.com/docs/build-skills), 클라이언트별 설치 및 패키지
공유 방법은 [설치 및 공유 안내](docs/INSTALLATION.md)를 참고하세요.

### Cursor Agent

프로젝트에 설치하려면 `.agents/skills/` 또는 `.cursor/skills/`, 사용자 단위로 설치하려면
`~/.agents/skills/` 또는 `~/.cursor/skills/`에 세 폴더를 복사합니다. Agent를 다시 열거나
새로고침하세요. Agent 채팅에서 `/`를 입력해 스킬 이름을 검색하고 직접 호출할 수도 있습니다.

Cursor에서는 현재 선택한 모델에 스킬이 제공됩니다. 프로젝트 단위 스킬은 모드와 함께 버전
관리할 수 있습니다. Cloud Agent에서 개인 `~/.cursor/skills/`를 사용하려면 Cursor 설정에서
스킬 동기화를 켜세요. Cursor의 로컬·원격 스킬 경로와 호출 방식은
[Cursor Agent Skills 문서](https://cursor.com/docs/skills)를 참고하세요.

## 사용 예시

파일을 수정하기 전에 기존 모드를 검토하려면 다음과 같이 요청할 수 있습니다.

> `$hoi4-review-debug` 이 모드를 검토해 줘. 기술 문서와 관련 현지화부터 읽고,
> 파일 간 참조, 변수의 수명, 주기적으로 실행되는 처리의 비용, 아이콘과 현지화,
> 의존성 호환성을 확인해 줘. 수정에 앞서 근거와 작업 계획을 알려 줘.

로그를 분석할 때는 가능한 경우 모드 경로, 대상 게임 버전, 사용 중인 의존성과 최신
`error.log`를 함께 제공하세요.

> 이 `error.log`를 분석해 줘. 이 모드, 의존 모드, 바닐라, 선택 사항인 미디어 리소스에서
> 생긴 오류를 구분해 줘. 반복 메시지는 원인별로 묶고, 각 원인을 해결할 최소 수정안을 알려 줘.

새 콘텐츠를 만들 때는 원하는 플레이 방식과 제약을 설명하세요.

> `$hoi4-content-builder` HOI4 1.19용으로 반복해서 사용할 수 있는 결정 세트를 만들어 줘.
> AI가 결정을 선택할 가중치를 정하고 한국어와 프로젝트의 나머지 지원 언어를 채워 줘.
> 구현하기 전에 해당 버전의 바닐라 문법을 확인하고 변경 파일을 정적으로 검증해 줘.

호환되는 에이전트는 요청이 `SKILL.md`의 설명과 맞으면 스킬을 자동으로 선택할 수 있습니다.
특정한 검토나 진단 절차를 적용하려면 스킬 이름을 직접 지정하세요.

## 주요 작업 절차

세 스킬 모두 [공통 작업 범위](skills/hoi4-pdx-modding/references/workflow-boundaries.md)를
따릅니다. 아직 유효한 증거는 재사용하고, 작은 변경은 영향을 받은 부분만 다시 점검합니다.
파일 간 연결 방식이나 작업 규칙이 바뀌면 관련 문서도 갱신합니다. 실제 게임을 테스트하는 경우에는 준비와 정리까지 시간
예산에 포함하고, 현재 세션·테스트 세이브·새 캠페인 가운데 적합한 진입점을 사용합니다.
사용자가 중단을 요청하면 새 작업을 시작하지 않고 현재 상태를 짧게 인계합니다.

### 기존 모드 개선

1. 프로젝트 기술 가이드, 인계 자료, 관련 게임 내 문구를 읽습니다.
2. 이벤트, 결정, 효과, 트리거, 변수, 플래그, 현지화, GUI, GFX가 어떻게 연결되는지 확인합니다.
3. 확인된 결함, 호환성 위험, 성능 문제, 제작자의 판단이 필요한 설계 선택을 구분합니다.
4. 승인이 필요한 경우 근거와 단계별 계획을 먼저 제시합니다.
5. 합의한 범위를 수정합니다. 작은 변경은 diff를 읽고, 일반 변경은 관련 파일만 검사합니다.
   규모가 크거나 여러 파일에 걸친 작업은 관련 범위만 넓혀 확인하고, 실제 게임에서 확인해야 할 부분을 기록합니다.

### 로그와 충돌 진단

1. `error.log` 메시지를 원인별로 묶고, 파싱·스코프·장비·이념·현지화 오류의 우선순위를 정합니다.
2. 타임스탬프, 활성 플레이세트, 충돌 직전의 조작을 실제 코드 경로와 대조합니다.
3. 필요하면 Windows 미니덤프를 분석하고, 판단의 확실성과 부족한 증거를 밝힙니다.
4. WinDbg나 Ghidra 사용, 전체 사용자 메모리 덤프 수집, 프로세스 연결, 하드웨어 데이터
   중단점 사용이 필요한 경우 해당 작업 범위에 대한 사용자 동의를 받습니다.

### 새 콘텐츠 구현

1. 자연어 요구 사항을 범위, 상태, 리소스, AI 행동, 호환성 조건, 완료 기준으로 정리합니다.
2. 대상 게임 설치본과 바닐라의 실제 사용 예, 활성화된 의존 모드에서 문법과 토큰을 확인합니다.
3. 검증된 템플릿으로 스크립트, GFX, 에셋, 현지화를 구현하고 실제 사용처와 연결합니다.
4. 변경 규모에 맞춰 인코딩, 파일 간 참조, 관련 주석과 문서를 확인합니다. 게임 안에서 확인이
   필요한 경우 합의된 범위와 시간 안에서 진행합니다.

## 지원 범위

- PDX 문법, 스코프 연결, 이벤트 대상, 변수와 플래그의 수명
- 이벤트, 결정, 국가중점, 국민정신, 인물, 군수 산업체, 장비, 기술, AI, 전투서열
- 자주 실행되는 `on_actions`, 전체 검색, 실행 주기, 이벤트로 갱신하는 방식
- 현지화 인코딩, 중복 키, 색상, 아이콘, 변수 서식, 스코프 함수, 다국어 템플릿
- GUI/GFX 등록, 국민정신·결정·특성 아이콘, 텍스처 경로, 오디오, 의존 모드의 에셋
- 로딩 화면 DDS, 이름을 지정한 에이스 조종사, 정보원 특성과 아이콘·고정 초상화
- 바닐라 및 대형 개편 모드와의 호환성, 버전 이행, 세이브의 상태 관리
- 게임 진행 흐름, 수치 밸런스, AI 사용 가능성, 플레이어 피드백과 대응 수단
- 기술 가이드, 인계 자료, 읽기 쉬운 주석, 검증 기록, 출시 전 점검
- `error.log`, 충돌 덤프, WinDbg와 사용자 동의를 받은 심층 진단

한국어로 작업할 때는 국가중점·국민정신·인물·결정·이벤트를 담은
[기본 현지화 템플릿](skills/hoi4-content-builder/assets/templates/localisation_l_korean.yml)과
색상·아이콘·동적 값·바인딩을 담은
[고급 현지화 템플릿](skills/hoi4-content-builder/assets/templates/localisation-advanced/localisation_advanced_l_korean.yml)을
사용할 수 있습니다.

## 검증 및 도구

- `evals/real-dialogue-regression.json`은 실제 대화에서 뽑아 익명화한 회귀 검증 사례입니다.
  원본 요청은 SHA-256 지문으로만 표시하며 비공개 세션이나 프로젝트 식별자는 공개하지 않습니다.
- Mod Doctor 2는 활성 플레이세트를 파악하고, Git 변경 파일을 중심으로 이전 기준과 비교할 수
  있습니다. 만료 날짜가 있는 제외 규칙을 적용하고, 확인된 결함과 추정에 따른 조사 후보를
  구분하며, Text·JSON·Markdown·SARIF로 결과를 출력합니다.
- 여러 파일로 구성된 키트에는 콘텐츠 구현 예제, 기술 연구를 통한 장비 해금, 게임 규칙에 따른
  시작 시점 초기화가 포함됩니다.
- `assets/template-manifest.json`에는 대상 빌드, 근거가 된 사용처, 검증 날짜, 필요한 검사가
  기록되어 있습니다. 검증 스크립트는 각 템플릿과 키트 파일이 한 번씩만 등록됐는지 확인합니다.
- 미디어 검사에서는 DDS 메타데이터, 명시적 참조, 측정 결과에 따른 변환 후보를 정리합니다.
  해시는 중복 확인이나 구체적인 내용 비교가 필요할 때 선택적으로 계산합니다. 로딩 화면,
  밉맵, 큐브맵, 모델 재질은 각 사용처의 요구 사항을 따릅니다.

## 검증 범위와 권한

스킬은 대상 게임 버전의 바닐라 파일, 설치본의 문서, 실제로 활성화된 의존 모드, 플레이어가
보는 현지화에서 근거를 확인하도록 안내합니다. 위키와 커뮤니티 자료는 조사 출발점으로 활용합니다.

정적 검사만으로는 GUI, MIO, 이벤트 스코프나 호환 분기의 실제 동작을 확인할 수 없습니다.
Steam 실행, 게임 조작, 진단 도구 설치, 리버스 엔지니어링, 프로세스 연결, 전체 메모리 수집이
필요한 경우 목적과 범위를 설명하고 사용자 동의를 받습니다.

## 다른 클라이언트

- Cursor는 `~/.cursor/skills/`, `~/.agents/skills/` 또는 프로젝트의 `.cursor/skills/`,
  `.agents/skills/`에 설치합니다. 채팅에서 `/`로 스킬을 검색할 수 있습니다.
- Claude Code는 `~/.claude/skills/` 또는 프로젝트의 `.claude/skills/`에 설치합니다.
- Gemini CLI는 `~/.gemini/skills/`, `~/.agents/skills/` 또는 지원되는 작업공간 경로에 설치합니다.
- 사용자 스킬 ZIP 업로드를 지원하는 클라이언트에서는 동일한 릴리스의 스킬 세 개를 설치합니다.
  스킬 하나만 설치하면 다른 스킬의 참조 자료와 작업 절차를 사용할 수 없습니다.

설치 경로는 클라이언트에 따라 달라질 수 있으므로 해당 클라이언트 문서를 참고하세요.
