# HOI4 AI 모딩 스킬

[简体中文](README.md) | [English](README_EN.md) | [日本語](README_JA.md) | [Русский](README_RU.md) | 한국어

**Codex, Google Antigravity, Cursor, Claude Code, Gemini CLI, ChatGPT**에서 *Hearts of Iron IV* 모드를 다루기 위한 3종 에이전트 스킬 세트입니다.

이 세트는 **기존 모드의 유지보수·진단·고도화에 무게중심**을 두고 있어 복잡한 코드 구조 파악, 파일 횡단 버그 추적, 성능 튜닝, 충돌 원인 규명에 특히 강합니다. 동시에 PDX 스크립트를 직접 쓰지 않고도 **일상 언어로 새 기능이나 완성된 모드를 처음부터 제작하는 역량**도 그대로 갖추고 있습니다.

요청 작성부터 스크립트·세이브 설계, GUI·셰이더, 에셋, 다국어 현지화, 오류 진단, Git 전달까지 한 번에 익히고 싶다면 일반 모드 개발 가이드를 확인하세요:
[한국어](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ko.md) |
[简体中文](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.zh-CN.md) |
[English](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.en.md) |
[日本語](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ja.md) |
[Русский](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ru.md).
이 가이드는 사용자가 요청할 때 꺼내 볼 수 있도록 따로 둔 문서이며, 일반 작업 중에는 스킬 진입점에 적힌 안내 규칙만 읽어 컨텍스트를 가볍게 유지합니다.

저장소에는 역할이 **물리적으로 분리된** 무의존 로컬 MCP 서버 두 가지도 함께 들어 있습니다.
- **읽기 전용 로컬 증거 도우미 `hoi4_local`**(Codex 플러그인에 기본 포함): 로컬 HOI4 설치 탐색, 식별자 참조 추적, Git 변경 파일 정적 검증, 로그 읽기, 미디어 메타데이터 확인을 맡습니다. 완전 오프라인·읽기 전용으로 동작하며 API 키가 필요 없습니다. 자세한 내용은 [로컬 플러그인 및 MCP 도우미](docs/LOCAL_MCP_PLUGIN.md)를 참고하세요.
- **선택형 실기 테스트 제어 서버 `hoi4_desktop`**(기본 비활성화, 필요 시 켜서 사용): Google Antigravity, Cursor, Claude Code, Gemini CLI처럼 내장 데스크톱 제어 기능이 없는 클라이언트에서 `hoi4.exe`, Paradox Launcher, Steam 창만 안전하게 캡처·조작할 수 있도록 프로세스 화이트리스트를 적용한 로컬 서버입니다. 자세한 내용은 [데스크톱 MCP 설정 가이드](docs/DESKTOP_MCP_SETUP.md)를 참고하세요.

## 세 가지 스킬 구성

| 스킬 | 맡은 역할 |
| --- | --- |
| `hoi4-review-debug` | 기존 모드 점검, 파일 횡단 Mod Doctor, 로그·충돌 진단, 성능 최적화, 호환성 검토, 밸런스·UX·에셋 감사 |
| `hoi4-pdx-modding` | PDX 문법과 스코프, 변수·세이브 수명 관리, 파일 간 계약, 현지화, 버전 이행, 기술 문서, 주석, 정적 검증 |
| `hoi4-content-builder` | 자연어 요구로 이벤트, 결정, 국가중점, 인물, 국민정신, MIO, GUI, AI, OOB, 지도, 음악, 모델 및 완성된 시스템 구축 |

**세 스킬은 꼭 함께 설치하세요.** `content-builder`가 아이디어를 실제 기능으로 엮고, `pdx-modding`이 대상 빌드의 문법과 계약을 지키며, `review-debug`가 진단·회귀 점검·실기 증거를 맡습니다. 서로의 참고 자료와 절차를 공유하므로 세트가 모두 갖춰져야 전체 워크플로가 매끄럽게 이어집니다.

## 설치 방법

### Codex 권장: 스킬 + 읽기 전용 로컬 MCP 플러그인

Windows에서 저장소를 복제하거나 압축을 푼 뒤 루트 폴더에서 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-codex-plugin.ps1
```

현재 사용자의 로컬 앱 데이터 폴더에 플러그인을 설치하고 Codex CLI에 등록합니다. 게임 파일 변경, Steam 실행, 외부 전송 없이 깔끔하게 끝납니다. 설치가 끝나면 **새 Codex 작업을 열어** 세 스킬과 다섯 가지 읽기 전용 도구를 바로 쓸 수 있으며, 저장소를 업데이트한 뒤에는 같은 명령을 다시 실행해 갱신하면 됩니다.

필수 환경: Windows, Python 3, Codex CLI(`ffprobe`가 있으면 오디오·비디오 스트림 정보까지 함께 읽어 줍니다). 자세한 안내는 [로컬 플러그인 및 MCP 도우미](docs/LOCAL_MCP_PLUGIN.md)에 있습니다.

### 스킬만 설치(클라이언트 공통)

[Releases](https://github.com/Fostanico/hoi4-ai-modding-skills/releases)에서 전체 패키지를 받거나 저장소를 복제한 뒤 `skills/` 아래 세 폴더를 원하는 범위에 복사합니다.

- **프로젝트 단위**(해당 모드와 함께 버전 관리): `<MOD_ROOT>/.agents/skills/`
- **사용자 단위**(여러 모드에서 공통 사용): `$HOME/.agents/skills/`

각 스킬 폴더 안의 `SKILL.md`, `references/`, `workflows/`, `assets/`, `scripts/`, `agents/` 구조는 그대로 유지하세요.

- **Codex / ChatGPT**: Codex는 변경을 보통 자동 인식하며, 목록에 안 보이면 재시작하면 됩니다. `/skills`로 확인하고 `$hoi4-review-debug`처럼 직접 호출할 수 있습니다. ChatGPT 데스크톱 앱에서는 사이드바 Skills 화면에서 관리합니다. 참고: [OpenAI 스킬 문서](https://learn.chatgpt.com/docs/build-skills).
- **Cursor**: 프로젝트 및 사용자 경로의 `.agents/skills/`, `.cursor/skills/`를 자동 탐색합니다. Agent를 다시 열거나 새로고침한 뒤 채팅에서 `/`로 검색·호출할 수 있습니다. 현재 선택한 어떤 모델에도 함께 전달되며, Cloud Agents에서 `~/.cursor/skills/`를 쓰려면 설정에서 Skills 동기화를 켜세요. 참고: [Cursor Agent Skills 문서](https://cursor.com/docs/skills).
- **Google Antigravity / Claude Code / Gemini CLI**: 각 클라이언트의 스킬 경로에 세 폴더를 배치하고, 필요에 따라 `hoi4_local` 및 `hoi4_desktop` MCP 서버를 연결할 수 있습니다.

클라이언트별 상세 경로와 배포 규칙은 [설치 및 공유 안내](docs/INSTALLATION.md)에 정리되어 있습니다.

## 바로 써 보는 요청 예시

**기존 모드를 손대기 전에 먼저 진단하기:**

> `$hoi4-review-debug` 이 모드를 검토해 줘. 기술 가이드와 관련 플레이어 문구부터 읽고, 파일 간 참조, 변수 수명, 주기 처리 비용, 아이콘, 현지화, 의존 모드 호환성을 짚어 줘. 파일을 고치기 전에 근거와 단계별 수정 계획을 먼저 보여 줘.

**`error.log`를 원인별로 깔끔하게 정리하기:**

> 이 `error.log`를 분석해 줘. 본 모드, 의존 모드, 바닐라, 선택 미디어 문제를 나누고 반복 로그를 근본 원인별로 묶어서 가장 깔끔한 최소 수정안을 알려 줘.

**자연어로 새 기능 만들기:**

> `$hoi4-content-builder` HOI4 1.20용으로 반복 실행할 수 있는 결정 세트를 만들어 줘. AI 선택 가중치와 한국어·영어·중국어·일본어·러시아어 현지화를 채우고, 현재 바닐라 문법을 먼저 확인한 뒤 변경 파일에 정적 검증을 돌려 줘.

작업 내용이 `SKILL.md` 설명과 맞으면 지원 클라이언트가 자동으로 알맞은 스킬을 고릅니다. 정해진 절차대로 꼼꼼히 감사하거나 진단하고 싶을 때는 스킬 이름을 직접 적어 두면 좋습니다.

## 핵심 작업 흐름

세 스킬은 모두 [공통 작업 경계](skills/hoi4-pdx-modding/references/workflow-boundaries.md)를 따릅니다. 아직 유효한 증거는 재사용하고, 국소 수정 뒤에는 영향받은 경로만 재검증하며, 실제 계약이 바뀔 때 문서를 갱신합니다. 짧은 실기 테스트에는 준비와 복구 시간까지 예산에 넣고, 중단을 요청하면 즉시 새 작업을 멈추고 깔끔하게 인계합니다.

### 1. 기존 모드 개선

1. 프로젝트 기술 가이드, 인계 노트, 플레이어가 보는 현지화부터 읽어 원래 의도를 정확히 파악합니다.
2. 이벤트, 결정, effects, triggers, 변수, 플래그, 현지화, GUI/GFX의 실제 연결을 파일 전반에 걸쳐 추적합니다.
3. 확정된 결함, 호환성 위험, 성능 병목, 제작자 판단이 필요한 게임플레이 선택지를 깔끔하게 구분합니다.
4. 승인이 필요한 작업은 코드를 건드리기 전에 근거와 단계별 계획을 먼저 제시합니다.
5. 합의한 범위만 수정하고 변경 규모에 맞춰 검증 깊이를 조절하며(작은 수정은 diff 확인, 일반 수정은 변경 파일 검증, 대규모 작업은 광역 점검), 게임 안에서 직접 확인해야 할 항목을 분명히 남깁니다.

### 2. 로그와 충돌 진단

1. `error.log`를 근본 원인별로 묶고 파싱, 스코프, 장비, 이념, 현지화 충돌을 최우선으로 해결합니다.
2. 타임스탬프, 활성 플레이세트, 충돌 직전 조작을 실제 코드 경로와 대조해 마지막 줄만 보고 섣불리 단정하지 않도록 합니다.
3. 필요할 때 Windows 미니덤프를 분석하며, 판단의 확신도와 부족한 근거를 투명하게 알립니다.
4. WinDbg, Ghidra, 전체 메모리 덤프, 프로세스 연결, 하드웨어 데이터 중단점은 단계별 사용자 동의를 거칩니다.

### 3. 새 콘텐츠 제작

1. 자연어 아이디어를 범위, 상태 소유권, 에셋, AI 규칙, 호환성 조건, 완료 기준으로 구조화합니다.
2. 대상 게임 빌드의 바닐라 파일, 설치 문서, 실제로 켜 둔 의존 모드에서 문법과 토큰을 확인합니다.
3. 검증된 템플릿과 멀티파일 키트로 스크립트, GFX, 에셋, 다국어 문구를 진입점까지 빠짐없이 연결합니다.
4. 변경 크기에 맞춰 인코딩, 참조, 주석과 문서를 점검하고, 게임 내 확인이 필요하면 허가된 범위와 예산 안에서 진행합니다.

## 다루는 영역

- **스크립트와 상태**: PDX 문법, 스코프 체인, 이벤트 대상, 변수와 플래그 수명
- **핵심 콘텐츠**: 이벤트, 결정, 국가중점, 국민정신, 인물, MIO, 장비, 기술, AI, 전투서열(OOB)
- **성능 최적화**: 고빈도 `on_actions`, 전체 순회 탐지, 이벤트 기반 갱신과 분할 처리
- **현지화**: UTF-8 BOM, 중복 키, 색상·아이콘 마커, 동적 변수 서식, 스코프 함수, 다국어 템플릿
- **UI와 미디어**: GUI/GFX 등록, 아이콘, 텍스처 경로, 오디오, 로딩 화면 DDS 규격, 네임드 에이스, 커스텀 정보원 특성과 고정 초상화
- **호환성과 이행**: 바닐라 및 대형 개편 모드 호환 분기, 버전 업그레이드, 기존 세이브 보호
- **플레이 경험과 문서**: 게임 루프, 수치 밸런스, AI 활용성, 피드백과 대응 수단, 기술 문서, 읽기 쉬운 주석, 배포 전 점검
- **심층 진단**: `error.log` 분석, 충돌 덤프, WinDbg, 동의 기반 네이티브 디버깅

한국어 모드 작업에는 [기본 한국어 현지화 템플릿](skills/hoi4-content-builder/assets/templates/localisation_l_korean.yml)과 색상·아이콘·동적 바인딩 예제를 담은 [고급 한국어 현지화 템플릿](skills/hoi4-content-builder/assets/templates/localisation-advanced/localisation_advanced_l_korean.yml)을 바로 활용할 수 있습니다.

## 엔지니어링 기반

- **실제 대화 회귀 세트**: `evals/real-dialogue-regression.json`에 익명화한 실전 모딩 과제를 모아 두었습니다. 원본 프롬프트는 SHA-256 지문으로만 추적해 비공개 대화와 개인 프로젝트 정보를 보호합니다.
- **Mod Doctor 2**: 활성 플레이세트 자동 해석, Git 변경 중심 감사, 이전 기준선 비교, 만료일이 있는 예외 규칙을 지원하며, 확정 결함과 추정 단서를 구분해 Text / JSON / Markdown / SARIF로 출력합니다.
- **멀티파일 키트**: 주요 콘텐츠 체인에 더해 기술-장비 해금과 게임 규칙 시작 초기화까지 완전한 세트로 제공합니다.
- **템플릿 매니페스트**: `assets/template-manifest.json`에 대상 빌드, 참고한 바닐라 사용처, 검증 날짜, 필수 검사를 기록하고 검증 스크립트로 누락 없이 관리합니다.
- **사용처 기반 미디어 감사**: DDS 메타데이터와 명시적 참조를 바탕으로 용량과 변환 후보를 점검합니다. 해시 계산은 중복·내용 비교가 필요할 때만 선택적으로 수행하며 로딩 화면, 밉맵, 큐브맵, 모델 재질의 고유 요건을 지킵니다.

## 증거와 안전 원칙

- **설치된 게임 빌드가 최종 기준**: 대상 버전의 바닐라 파일, 설치 문서, 활성 의존 모드, 플레이어 현지화에서 근거를 확인합니다. 위키와 커뮤니티 가이드는 좋은 단서로 활용하되 최종 판단은 현재 빌드에 맞춥니다.
- **정적 검증과 실기 검증의 역할 분담**: 문법, 참조, 인코딩, 연결은 정적 검증으로 잡고, GUI 표시·MIO 상호작용·복잡한 스코프·호환 분기는 게임 안에서 직접 확인합니다.
