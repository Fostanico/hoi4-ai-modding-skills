# HOI4 AI Modding Skills

[简体中文](README.md) | [English](README_EN.md) | 日本語 | [Русский](README_RU.md) | [한국어](README_KO.md)

**Codex・Google Antigravity・Cursor・Claude Code・Gemini CLI・ChatGPT** で『Hearts of Iron IV』の MOD を扱うための 3 つ組 Agent Skills です。

本キットは**既存 MOD の保守・診断・改善を主軸**にしており、大規模プロジェクトの構造把握、ファイル横断の不具合追跡、性能チューニング、クラッシュ原因の特定に強みを発揮します。あわせて、PDX スクリプトを自分で書かずに**自然言語のアイデアから新機能や MOD 全体を制作する能力**もそのまま備えています。

依頼の書き方からスクリプト・セーブ設計、GUI・シェーダー、素材、多言語対応、排錯、引き渡しまでを体系的にまとめた汎用開発ガイドはこちら：
[日本語](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ja.md) |
[简体中文](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.zh-CN.md) |
[English](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.en.md) |
[Русский](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ru.md) |
[한국어](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.ko.md)。
人間の読者向けに用意した資料のため、各 Skill には案内ルールだけを置き、通常作業のコンテキストを圧迫しない構成にしています。

本リポジトリには、役割を**物理的に分離**したゼロ依存のローカル MCP サーバーも 2 種類収録しています。
- **読み取り専用の証拠収集サーバー `hoi4_local`**（Codex Plugin に同梱）：ローカルの HOI4 導入環境検出、識別子の参照追跡、Git 変更ファイルの軽量検証、ログ読み取り、メディアのメタデータ確認を行います。完全ローカル・読み取り専用で、API キーも不要です。詳しくは [ローカルプラグインと MCP ヘルパー](docs/LOCAL_MCP_PLUGIN.md) をご覧ください。
- **任意有効化の実機テストサーバー `hoi4_desktop`**（既定では無効）：Google Antigravity・Cursor・Claude Code・Gemini CLI などデスクトップ操作機能を持たないクライアント向けに、`hoi4.exe`・Paradox Launcher・Steam のみに限定した安全なスクリーンショット取得と入力操作を提供します。詳しくは [ローカルデスクトップ制御 MCP 設定ガイド](docs/DESKTOP_MCP_SETUP.md) をご覧ください。

## 3 つの Skills の役割分担

| Skill | 主な担当 |
| --- | --- |
| `hoi4-review-debug` | 既存 MOD の点検、ファイル横断 Mod Doctor、ログ・クラッシュ診断、性能調整、互換性確認、バランス・UX・素材レビュー |
| `hoi4-pdx-modding` | PDX 構文とスコープ、変数・セーブのライフサイクル、ファイル間契約、ローカライズ、バージョン移行、技術文書、コメント、静的検証 |
| `hoi4-content-builder` | 自然言語の要望からイベント、ディシジョン、国家方針、キャラクター、国民精神、MIO、GUI、AI、OOB、マップ、音楽、モデル、システム全体を制作 |

**3 つの Skills は必ずセットで導入してください。** `content-builder` が構想を動く機能に組み上げ、`pdx-modding` が対象バージョンの構文と契約を守り、`review-debug` が診断・回帰確認・実機証拠を担います。互いの資料と手順を参照し合うため、3 つ揃えて初めて本来の力を発揮します。

## インストール

### Codex 推奨構成：Skills ＋ 読み取り専用ローカル MCP

Windows でリポジトリをクローンまたは展開し、ルートディレクトリで実行します。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-codex-plugin.ps1
```

現在のユーザーのローカルアプリデータ領域にプラグインを配置し、Codex CLI へ登録します。ゲームファイルの改変や Steam 起動、外部送信は一切行いません。完了後に**新しい Codex タスクを開く**と 3 つの Skills と 5 つの読み取り専用ツールが利用できるようになります。更新時は同じコマンドを再実行するだけです。

動作環境：Windows、Python 3、Codex CLI（`ffprobe` が入っていれば音声・動画ストリーム情報も取得できます）。詳細は [ローカルプラグインと MCP ヘルパー](docs/LOCAL_MCP_PLUGIN.md) を参照してください。

### Skills のみを導入（各クライアント共通）

[Releases](https://github.com/Fostanico/hoi4-ai-modding-skills/releases) からリリース一式を入手するかリポジトリをクローンし、`skills/` 配下の 3 ディレクトリを次のいずれかへコピーします。

- **プロジェクト単位**（MOD と一緒に管理）：`<MOD_ROOT>/.agents/skills/`
- **ユーザー単位**（複数 MOD で共用）：`$HOME/.agents/skills/`

各 Skill 内の `SKILL.md`、`references/`、`workflows/`、`assets/`、`scripts/`、`agents/` の相対配置はそのまま保ってください。

- **Codex / ChatGPT**：Codex は通常自動で変更を検出します（反映されない場合は再起動）。`/skills` で一覧表示し、`$hoi4-review-debug` のように明示呼び出しもできます。ChatGPT デスクトップ版はサイドバーの Skills ページで確認できます。参考：[OpenAI Skills ドキュメント](https://learn.chatgpt.com/docs/build-skills)。
- **Cursor**：プロジェクトおよびユーザー配下の `.agents/skills/`・`.cursor/skills/` を自動検出します。Agent を開き直すか更新し、チャットで `/` から名前指定もできます。選択中の任意のモデルで利用でき、Cloud Agents で `~/.cursor/skills/` を使う場合は設定で Skills 同期を有効にしてください。参考：[Cursor Agent Skills ドキュメント](https://cursor.com/docs/skills)。
- **Google Antigravity / Claude Code / Gemini CLI**：各クライアントの Skills 配置先に 3 ディレクトリを置き、必要に応じて `hoi4_local` や `hoi4_desktop` を接続できます。

全クライアント別の手順と配布ガイドは [インストールと共有のガイド](docs/INSTALLATION.md) にまとめています。

## 依頼の例

**既存 MOD を変更前にレビューする：**

> `$hoi4-review-debug` この MOD をレビューしてください。まず技術文書と関連するプレイヤー向けテキストを読み、ファイル間の参照、変数の寿命、定期処理の負荷、アイコン、ローカライズ、依存 MOD との互換性を点検してください。ファイルを変更する前に、証拠と段階的な修正案を出してください。

**`error.log` を原因別に整理する：**

> この `error.log` を解析してください。本 MOD・依存 MOD・バニラ・任意素材に分けて整理し、同じ根本原因のログをまとめて、それぞれ最小限の修正案を提示してください。

**自然言語から新機能を作る：**

> `$hoi4-content-builder` HOI4 1.20 向けに繰り返し実行できるディシジョン群を制作してください。AI の選択重みと、英語・簡体字中国語・ロシア語・日本語・韓国語のローカライズを揃え、現在のバニラ構文を確認したうえで変更ファイルの静的検証を行ってください。

依頼内容が `SKILL.md` の説明と合致すれば対応クライアントが自動で Skill を選びます。決まった手順でレビューや診断を進めたいときは Skill 名を明示すると確実です。

## 主なワークフロー

3 つの Skills は[共通のワークフロー境界](skills/hoi4-pdx-modding/references/workflow-boundaries.md)に沿って動きます。有効な証拠を再利用し、局所修正では影響範囲だけを再検証し、仕様が変わったときだけ文書を更新します。短時間の実機テストは準備と復元を含めて予算内に収め、停止を指示されれば即座に作業を切り上げて要点を引き継ぎます。

### 1. 既存 MOD の改善

1. 技術文書、引き継ぎ記録、プレイヤー向けテキストを読み、元の設計意図を把握します。
2. イベント、ディシジョン、effects、triggers、変数、flags、ローカライズ、GUI/GFX のつながりをファイル横断で整理します。
3. 確定した不具合、互換性リスク、性能課題、作者の判断が要るゲーム設計を明確に切り分けます。
4. 承認が必要な作業は、編集に入る前に証拠と段階的な計画を提示します。
5. 合意範囲だけを修正し、差分の規模に応じた検証（小修正は diff 目視、通常修正は変更ファイル検証、大規模改修は広域チェック）を実施したうえで、実機確認が必要な箇所を明記します。

### 2. ログとクラッシュ診断

1. `error.log` を根本原因ごとにまとめ、構文解析、スコープ、装備、イデオロギー、ローカライズ競合を最優先で片付けます。
2. ログ時刻、有効なプレイセット、直前の操作を実際のコード経路と突き合わせ、末尾の 1 行だけで原因を決めつけないようにします。
3. 必要に応じて Windows minidump を読み、確度と不足している証拠を明示します。
4. WinDbg、Ghidra、完全ユーザーダンプ、プロセスへのアタッチ、ハードウェアブレークポイントは段階ごとに同意を得て進めます。

### 3. 新しいコンテンツ制作

1. 自然言語の要望を、範囲、状態管理、素材、AI 挙動、互換性、受け入れ基準へと整理します。
2. 対象バージョンのバニラ文書・実際の使用側コード・有効な依存 MOD に照らして構文とトークンを確認します。
3. 検証済みテンプレートとキットからスクリプト、GFX、素材、多言語テキストを切れ目なく組み上げます。
4. 変更規模に見合う文字コード・参照・文書チェックを行い、実機検証が必要なときは許可と予算を守ります。

## 対応領域

- **スクリプトと状態**：PDX 構文、スコープ連鎖、イベントターゲット、変数とフラグのライフサイクル
- **中核コンテンツ**：イベント、ディシジョン、国家方針、国民精神、キャラクター、MIO、装備、技術、AI、OOB
- **性能改善**：高頻度 `on_actions`、全体走査の洗い出し、イベント駆動・分割処理への置き換え
- **ローカライズ**：UTF-8 BOM、重複キー、色・アイコン記号、変数書式、scope functions、多言語テンプレート
- **画面と素材**：GUI/GFX 登録、アイコン、テクスチャパス、音声、ロード画面 DDS 規約、名前付きエース、独自諜報員特性と固定ポートレート
- **互換性と移行**：バニラおよび大型改変 MOD との互換分岐、バージョン移行、既存セーブの安全な維持
- **体験と文書**：ゲームプレイ循環、数値バランス、AI 利用性、フィードバックと対抗手段、技術文書、読みやすいコメント、リリース前点検
- **高度な診断**：`error.log` 整理、クラッシュダンプ、WinDbg、同意を得たネイティブ解析

## 開発を支える仕組み

- **実対話ベースの回帰セット**：`evals/real-dialogue-regression.json` に匿名化した実務タスクを収録。SHA-256 フィンガープリントで出典を追跡しつつ、非公開会話や個別プロジェクト情報は外に出しません。
- **Mod Doctor 2**：有効なプレイセット解決、Git 変更範囲の限定監査、過去ベースラインとの比較、期限付き抑制ルールに対応し、確定不具合と推測の手掛かりを分けて Text / JSON / Markdown / SARIF で出力します。
- **複数ファイルキット**：定番コンテンツ連鎖に加え、技術による装備解禁やゲームルールによる開始時初期化まで一式で備えています。
- **テンプレート管理台帳**：`assets/template-manifest.json` に対象ビルド、参照したバニラ実例、確認日、必須チェックを記録し、検証器で全ファイル登録を保証します。
- **用途別メディア監査**：DDS メタデータと明示的参照から容量と変換候補を評価。ハッシュ計算は明示的な重複・一致確認時のみ行い、ロード画面・ミップマップ・キューブマップ・モデル材質の要件を守ります。

## 証拠と安全の原則

- **対象ビルドの実物を最優先**：対象バージョンのバニラコード、同梱文書、実際に有効な依存 MOD、プレイヤー向けテキストを根拠にします。Wiki や解説記事は調査の手掛かりとして活かし、最終判断は手元のビルドで行います。
- **静的検証と実機検証の役割分担**：構文・参照・文字コード・接続の正確さは静的検証で固め、GUI 表示、MIO 動作、複雑なスコープや互換分岐はゲーム内で確認します。
- **高権限操作は必ず事前承認**：Steam 起動、ゲーム操作、診断ツール導入、リバースエンジニアリング、プロセス接続、メモリ全体採取を行うときは、目的・範囲・リスクを説明し、同意を得てから実行します。
