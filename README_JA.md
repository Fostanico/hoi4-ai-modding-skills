# HOI4 AI Modding Skills

[简体中文](README.md) | [English](README_EN.md) | 日本語 | [Русский](README_RU.md)

Codex、ChatGPT、Cursor、Claude Code、Gemini CLI で『Hearts of Iron IV』の MOD を
保守・診断・改善・制作するための、3 つの Agent Skills を収録しています。

現在は既存 MOD の保守を重視しています。未知のコード構成を把握し、ファイルをまたぐ
不具合を追跡し、性能や互換性を確認し、クラッシュの証拠から具体的な修正案を作ります。
PDX スクリプトを知らない方でも、自然言語でアイデアを伝え、新しいコンテンツや
MOD 全体を制作するための手順を利用できます。

機能や依頼の書き方、具体例については、
[英語のユーザーガイド](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.en.md)
または[簡体字中国語版](skills/hoi4-pdx-modding/assets/user-guides/hoi4-modding-guide.zh-CN.md)
をご覧ください。ガイドは必要なときにユーザーへ提供する資料です。各 Skill の
入口には提供方法だけを記載し、通常はガイド本文を読み込まない構成にしています。

このリポジトリは、任意で利用できる **Codex Plugin** にも対応しています。
プラグインは 3 つの Skills とローカルの読み取り専用 MCP サーバーをまとめて配布します。
Skills が開発・レビュー・検証の手順を定め、MCP サーバーが HOI4 のインストール先の
検出、識別子の参照追跡、Git 変更ファイルの検証、ログの読み取り、メディアの
メタデータ確認を行います。MCP の処理はすべてローカルで実行され、クラウド上の
HOI4 ファイル集や OpenAI API キーは不要です。ゲームの起動や MOD ファイルの
書き換えを行う機能はありません。構成、ツールのインターフェース、動作範囲は
[ローカルプラグインと MCP ヘルパー](docs/LOCAL_MCP_PLUGIN.md)を参照してください。

## 収録 Skills

| Skill | 主な用途 |
| --- | --- |
| `hoi4-review-debug` | 既存 MOD の改善、ファイル横断の Mod Doctor、ログ・クラッシュ解析、性能、互換性、バランス、UX、アイコン・素材の点検 |
| `hoi4-pdx-modding` | PDX スクリプト、スコープ、ライフサイクル、ファイル間の仕様、ローカライズ、バージョン移行、技術文書、コメント、静的検証 |
| `hoi4-content-builder` | 自然言語の要望からイベント、ディシジョン、国家方針、キャラクター、国民精神（ideas）、MIO、GUI、AI、OOB、マップ、音楽、モデル、システム全体を制作 |

**3 つの Skills をまとめてインストールすることを推奨します。** 検証規則や
ワークフロー、参照資料を共有しているためです。`content-builder` は要望を
コンテンツに落とし込み、`pdx-modding` は言語と対象バージョンの確認を担い、
`review-debug` は保守・回帰確認・実行時の証拠を扱います。単独でも入口の説明は
読み込めますが、他の Skill の参照資料が欠けるため、全体の手順は利用できません。

## インストール

### Codex での推奨構成：Skills とローカルツール

Windows でこのリポジトリをクローンまたは展開し、リポジトリのルートで実行します。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-codex-plugin.ps1
```

スクリプトは現在のユーザーのローカルアプリデータ領域にプラグイン全体を配置し、
Codex CLI を通じて登録します。HOI4 の変更、ゲームの起動、ローカルファイルの
アップロードは行いません。完了後に新しい Codex タスクを作成すると、3 つの Skills と
5 つの読み取り専用ローカルツールを利用できます。リポジトリを更新した後は、
同じコマンドを再実行してプラグインを更新できます。

必要な環境は Windows、Python 3、Codex CLI です。`ffprobe` は任意で、
音声・動画ストリームの追加情報を取得するときに使います。詳しい動作範囲と
トラブルシューティングは[ローカルプラグインと MCP ヘルパー](docs/LOCAL_MCP_PLUGIN.md)
を参照してください。

### Skills のみをインストール

[Releases](https://github.com/Fostanico/hoi4-ai-modding-skills/releases) から
完全版パッケージをダウンロードするか、リポジトリをクローンします。
`skills/` 内の 3 つのディレクトリを、次のいずれかへコピーしてください。

- 現在の MOD リポジトリ：`<MOD_ROOT>/.agents/skills/`
- ユーザー共通：`$HOME/.agents/skills/`

プロジェクト内への配置は MOD と一緒に管理する場合に、ユーザー共通の配置は
複数の MOD で利用する場合に適しています。各 Skill の `SKILL.md`、`references/`、
`workflows/`、`assets/`、`scripts/`、`agents/` の相対位置を維持してください。

プラグイン非対応のクライアントでも、この方法で Skills を利用できます。
ローカル MCP ツールはインストールされません。

通常、Codex は変更を自動検出します。表示されない場合は再起動してください。
Codex CLI や IDE 拡張では `/skills` で一覧を確認し、`$hoi4-review-debug` のように
名前を指定して呼び出せます。ChatGPT デスクトップアプリではサイドバーの
Skills ページで確認できます。配置先と呼び出し方法は
[OpenAI の Skills ドキュメント](https://learn.chatgpt.com/docs/build-skills)も参照してください。

ほかのプラットフォームや配布方法については[インストールと共有のガイド](docs/INSTALLATION.md)
をご覧ください。

### Cursor Agent

Cursor はプロジェクトの `.agents/skills/` または `.cursor/skills/`、および
ユーザー共通の `~/.agents/skills/` または `~/.cursor/skills/` から Skills を検出します。
`skills/` 内の 3 ディレクトリをいずれかの場所へコピーし、Agent を開き直すか
更新してください。Agent のチャットで `/` を入力し、Skill 名を検索して明示的に
呼び出すこともできます。

Skills は Cursor Agent から現在選択中のモデルへ渡され、特定のモデルには依存しません。
プロジェクト内の Skills は MOD と一緒にバージョン管理できます。個人用の
`~/.cursor/skills/` を Cloud Agents で使う場合は、Cursor の設定で Skills の同期を
有効にしてください。Skills のコピーだけでは Codex 専用のローカル MCP ヘルパーは
導入されません。配置先、呼び出し方法、リモート Agent での制約は
[Cursor Agent Skills の公式ドキュメント](https://cursor.com/docs/skills)を参照してください。

## 使用例

既存 MOD の保守は、まずファイルを変更しないレビューから始められます。

> `$hoi4-review-debug` この MOD をレビューしてください。最初に技術文書と関連する
> プレイヤー向けテキストを読み、ファイル間の参照、変数のライフサイクル、定期処理の
> 性能、アイコン、ローカライズ、依存 MOD との互換性を確認してください。
> ファイルを変更する前に、証拠と修正案を報告してください。

ログの調査では、可能であれば MOD のパス、対象のゲームバージョン、有効な依存 MOD、
最新の `error.log` を一緒に提示してください。

> この `error.log` を解析してください。この MOD、依存 MOD、バニラ、任意の素材に
> 起因する問題を区別し、同じ根本原因のメッセージをまとめて、それぞれに最小限の
> 修正案を示してください。

新しいコンテンツでは、遊び方の目標と制約をそのまま伝えられます。

> `$hoi4-content-builder` HOI4 1.19 向けに、繰り返し実行できるディシジョン群を
> 作成してください。AI の選択重みと、英語・簡体字中国語・ロシア語・日本語の
> ローカライズを含め、実装前に現在のバニラの構文を確認し、完成後に静的検証を行ってください。

毎回 Skill 名を書く必要はありません。対応する Agent は、依頼が `SKILL.md` の
説明に合致すれば自動で選択できます。特定のレビューや診断手順を使いたい場合は、
名前を明示すると便利です。

## 主なワークフロー

3 つの Skills は[共通のワークフロー規則](skills/hoi4-pdx-modding/references/workflow-boundaries.md)
に従います。有効な証拠は再利用し、局所的な変更の後は影響する部分だけを再確認し、
技術文書は仕様が変わったときに更新します。短時間のテストには準備と後片付けも含め、
調査対象に合う現在のセッション、テスト用セーブ、新規ゲームを選びます。
ユーザーから停止の指示があれば作業を止め、簡潔に引き継ぎます。

### 既存 MOD の改善

1. プロジェクトの技術文書、引き継ぎ記録、関連するプレイヤー向けテキストを読み、機能の意図を確認します。
2. イベント、ディシジョン、effects、triggers、変数、flags、ローカライズ、GUI、GFX のファイル間の関係を整理します。
3. 確認できた不具合、互換性リスク、性能問題、作者の判断が必要なゲーム設計上の選択を分けます。
4. 承認が必要な場合は、変更前に証拠と段階的な修正案を提示します。
5. 許可された範囲だけを変更します。小さな差分は目視確認、通常の変更は変更ファイルの検証、大きな変更は関連する広範囲の確認を選びます。不要な検証で利用枠を消費せず、実機での証拠が必要な点を明示します。

### ログとクラッシュの診断

1. `error.log` を根本原因ごとに整理し、構文解析、スコープ、装備、イデオロギー、ローカライズの不具合を優先します。
2. ログの時刻、有効なプレイセット、クラッシュ直前の操作を実際のコード経路と照合します。最後のログ行だけを原因と決めつけません。
3. 必要に応じて Windows minidump を解析し、結論の確度と不足している証拠を報告します。
4. WinDbg、Ghidra、完全ユーザーダンプ、プロセスへのアタッチ、ハードウェアデータブレークポイントは、段階ごとにユーザーの同意を得て扱います。

### 新しいコンテンツの制作

1. 自然言語の要望を、範囲、状態、素材、AI の動作、互換性、受け入れ条件に整理します。
2. 対象バージョンのバニラ文書、実際の使用例、有効な依存 MOD に照らして構文とトークンを確認します。
3. 検証済みテンプレートやキットを使い、スクリプト、GFX、素材、ローカライズを接続して、孤立した定義を残さないようにします。
4. 変更に応じて文字コード、ファイル間の参照、関連するコメントと技術文書を確認します。実機での証拠が必要な場合は、許可された範囲と予算に従います。

## 確認できる内容

- PDX 構文、スコープの連鎖、イベントターゲット、変数とフラグのライフサイクル
- イベント、ディシジョン、国家方針、国民精神、キャラクター、MIO、装備、技術、AI、戦闘序列（OOB）
- `on_actions` の高頻度処理、全体走査、実行頻度、イベント駆動への置き換え
- ローカライズの文字コード、重複キー、色、アイコン、変数書式、scope functions、多言語テンプレート
- GUI/GFX の登録、国民精神・ディシジョン・特性のアイコン、テクスチャパス、音声、依存素材
- ロード画面の DDS 制約、名前付きエースパイロット、諜報員の独自特性・アイコン・固定ポートレート
- バニラや大型 MOD との互換分岐、バージョン移行、セーブのライフサイクルに関するリスク
- ゲームプレイの循環、数値バランス、AI が利用できるか、フィードバック、対抗手段、プレイヤー体験
- 技術文書、引き継ぎ、読みやすいコメント、検証記録、リリース前の確認
- `error.log`、クラッシュダンプ、WinDbg、同意を得た高度なネイティブ診断

## 開発支援機能

- 実際の対話に基づく回帰ケースを `evals/real-dialogue-regression.json` に収録しています。
  依頼は匿名化し、元の依頼は SHA-256 フィンガープリントで識別します。
  非公開の会話やプロジェクト識別子は公開しません。
- Mod Doctor 2 は有効なプレイセットの読み取り、Git 変更範囲の確認、過去の基準との比較、
  期限付きの抑制ルールに対応し、Text、JSON、Markdown、SARIF を出力できます。
  確認済みの問題と推測に基づく手がかりを区別します。
- 複数ファイルのキットには、各種コンテンツの連携に加え、技術による装備の解禁や
  ゲームルールに基づく開始時の初期化が含まれます。
- `assets/template-manifest.json` は対象ビルド、参照した使用例、確認日、必要な検証を
  記録します。検証器はすべてのテンプレートとキットのファイルが一度ずつ登録されているかを確認します。
- メディアの確認では DDS メタデータ、明示的な参照、変換候補を調べます。
  ハッシュ計算は具体的な重複確認や内容比較が必要な場合に限ります。
  ロード画像、ミップマップ、キューブマップ、モデル材質は、それぞれの用途に応じて扱います。

## 動作範囲と制約

Skills は、対象バージョンのゲームファイル、インストールに含まれる文書、実際に
有効な依存 MOD、プレイヤー向けテキストに照らして確認するよう Agent に指示します。
Wiki やコミュニティの解説は調査の手がかりになりますが、現在のバージョンの証拠には代えられません。

静的検証だけでは、GUI、MIO、イベントのスコープ、互換分岐が実際に動くことまでは
証明できません。Steam の起動、ゲームの操作、診断ツールの導入、リバースエンジニアリング、
プロセスへのアタッチ、メモリ全体の取得には、目的と範囲の説明、およびユーザーの同意が必要です。

## その他のクライアント

- Cursor：`~/.cursor/skills/`、`~/.agents/skills/`、またはプロジェクトの
  `.cursor/skills/`、`.agents/skills/`。`/` で検索して呼び出せます。
- Claude Code：`~/.claude/skills/` またはプロジェクトの `.claude/skills/`。
- Gemini CLI：`~/.gemini/skills/`、`~/.agents/skills/`、または対応するワークスペースのディレクトリ。
- カスタム Skills のアップロードに対応するクライアント：同じリリースの 3 つの Skill ZIP を
  すべてインストールしてください。単独インストールは、ほかの Skill の機能が欠けることを
  理解している上級者向けです。

検出されるディレクトリはクライアントの更新で変わることがあります。
導入前に各プラットフォームの最新ドキュメントを確認してください。
